# 校园智能安防系统后端接入手册

本文档面向负责独立后端开发的同学。前端已经通过统一 API 客户端与业务页面解耦；后端只要实现本文约定的 REST、WebSocket 和 MJPEG 协议，即可替换当前 FastAPI Demo 后端。

> 文档状态：与系统 2.0.0 同步  
> 契约版本：1.0  
> 最后核对：2026-09-23

## 1. 接入目标

前端只负责：

- 页面展示和表单交互；
- 定时拉取状态；
- 接收实时告警；
- 展示后端提供的检测、证据和统计结果。

后端负责：

- 用户登录、会话和权限；
- 视频检测、传感器、门禁等业务逻辑；
- 数据库存取；
- 告警生成、截图保存和实时推送；
- DS 或其他多模态融合计算。

前端不会自行计算风险分、Bel、Pl、Unknown 或 Conflict。后端返回 `null` 时，前端显示 `—`，不会按 `0` 处理。

## 2. 契约版本

当前契约版本：`1.0`。

前端对所有 REST 请求发送：

```http
Accept: application/json
X-Campus-Contract-Version: 1.0
```

后端应暂时兼容 `1.x` 客户端。字段只能以“新增可选字段”的方式扩展；不要直接删除或重命名已有字段。

当前 Demo 提供机器可读清单：

```text
GET /api/integration/manifest
```

## 3. 前端连接配置

统一客户端文件：

```text
app/static/js/api-client.js
```

接口常量集中在 `CampusAPI.endpoints`，页面不直接决定后端域名。

### 3.1 默认同源模式

不设置环境变量时，前端继续调用当前地址：

```text
http://127.0.0.1:8000/api/...
ws://127.0.0.1:8000/ws/alarms
http://127.0.0.1:8000/video_feed
```

### 3.2 独立后端直连

Windows PowerShell：

```powershell
$env:CAMPUS_API_BASE_URL = "http://127.0.0.1:9000"
$env:CAMPUS_WS_BASE_URL = "ws://127.0.0.1:9000"
python run.py
```

Windows CMD：

```bat
set CAMPUS_API_BASE_URL=http://127.0.0.1:9000
set CAMPUS_WS_BASE_URL=ws://127.0.0.1:9000
python run.py
```

配置值不要以 `/` 结尾。修改环境变量后需要重启前端服务。

### 3.3 推荐部署方式

优先使用同源反向代理：

```text
/                 -> 当前 Jinja2 页面服务
/static/*         -> 当前静态文件
/api/*            -> 新后端
/ws/*             -> 新后端 WebSocket
/video_feed       -> 新后端视频流
```

同源方案可以继续使用 Session Cookie，且图片、MJPEG 和 WebSocket 不需要额外处理跨域凭证。

## 4. 认证与权限

### 4.1 推荐：Session Cookie

- 登录成功后设置 `HttpOnly` Session Cookie；
- REST 返回 `401` 表示未登录，`403` 表示角色无权限；
- WebSocket 握手时校验同一 Cookie；
- Cookie 推荐设置 `SameSite=Lax`；HTTPS 部署时设置 `Secure`。

当前页面登录路由仍是：

```text
GET  /login
POST /login  Content-Type: application/x-www-form-urlencoded
GET  /logout
```

登录字段：`username`、`password`。

### 4.2 可选：Bearer Token

统一客户端预留：

```javascript
CampusAPI.setAccessToken("short-lived-access-token");
```

设置后 REST 自动发送：

```http
Authorization: Bearer short-lived-access-token
```

WebSocket 会使用：

```text
/ws/alarms?access_token=short-lived-access-token
```

如果采用该方式，只能使用短期 Token，并必须使用 HTTPS/WSS。MJPEG `<img>` 无法附加 Authorization Header，因此视频流应使用同源 Cookie、短期签名 URL 或反向代理。

当前项目自带的 FastAPI Demo 后端以 Session Cookie 为正式鉴权方式；前端已经预留 Bearer Token，但独立后端若选择 Token 模式，必须自行实现 Token 的签发、校验、刷新和撤销。不要把 WebSocket 查询参数中的 Token 写入访问日志。

### 4.3 角色

| 角色 | 权限范围 |
| --- | --- |
| `admin` | 全部接口 |
| `security` | 监控、告警、门禁、传感器、设备 |
| `teacher` | 告警、证据、访客、地图、大屏 |
| `viewer` | 地图、大屏、系统状态 |

后端必须执行权限校验，不能只依赖前端隐藏菜单。

## 5. 通用规范

### 5.1 时间

统一返回 ISO-8601：

```json
"2026-09-23T14:32:18"
```

允许带时区：

```json
"2026-09-23T14:32:18+08:00"
```

同一部署中应保持一致。不要返回本地化字符串。

### 5.2 空值

- 未知数值返回 `null`；
- 未知时间返回 `null`；
- 空列表返回 `[]`；
- 不要用 `0` 代替“无数据”；
- 不要用空字符串代替缺失数值。

### 5.3 成功响应

列表查询可以直接返回数组。操作接口建议返回：

```json
{
  "ok": true,
  "message": "Detection started",
  "data": {}
}
```

### 5.4 错误响应

使用正确 HTTP 状态码，并返回：

```json
{
  "detail": "Sensor not found"
}
```

建议状态码：

| 状态码 | 含义 |
| --- | --- |
| `400` | 参数格式或枚举值错误 |
| `401` | 未登录或 Token 失效 |
| `403` | 已登录但无权限 |
| `404` | 数据不存在 |
| `409` | 唯一键或状态冲突 |
| `422` | 请求体校验失败 |
| `500` | 未处理的服务端错误 |
| `503` | 模型或硬件暂不可用 |

## 9. WebSocket 实时告警

连接地址：

```text
ws://host/ws/alarms
```

每次推送一个 JSON 对象：

```json
{
  "id": 1024,
  "event_type": "fire_detected",
  "event_level": "high",
  "message": "检测到疑似火焰",
  "location": "食堂",
  "snapshot_path": "/static/snapshots/fire_1024.jpg",
  "person_count": 2,
  "confidence": 0.873,
  "created_at": "2026-09-23T14:32:18+08:00",
  "status": "unhandled",
  "map_point_id": 3
}
```

要求：

- 登录失效时拒绝握手或使用关闭码 `1008`；
- 同一事件只推送一次；
- `id` 必须与 `/api/alarms` 中的记录一致；
- `map_point_id` 可以为 `null`；
- 断线重连由前端负责；
- 后端不要求客户端定时发送业务消息。

## 10. MJPEG 视频流

```text
GET /video_feed
Content-Type: multipart/x-mixed-replace; boundary=frame
```

分片格式：

```text
--frame\r\n
Content-Type: image/jpeg\r\n
\r\n
<JPEG bytes>\r\n
```

要求：

- 无摄像头时仍返回模拟帧；
- 客户端断开后及时结束生成器；
- 不要缓存完整视频；
- 推荐 10-25 FPS；
- 跨域 JWT 场景优先通过同源代理转发该接口。

## 11. 截图地址

`snapshot_path` 可以是：

- 同源相对地址：`/static/snapshots/a.jpg`；
- 完整 HTTPS 地址；
- 有时效的签名 URL。

独立后端返回相对地址时，前端会自动拼接 `CAMPUS_API_BASE_URL`。

## 12. CORS 配置

如果必须跨域直连，新后端需要允许：

```text
Origin: 前端实际地址，例如 http://127.0.0.1:8000
Methods: GET, POST, PUT, DELETE, OPTIONS
Headers: Content-Type, Authorization, X-Campus-Contract-Version
Credentials: true（使用 Cookie 时）
```

使用 Cookie 时不能同时设置：

```text
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
```

当前 Demo 后端可通过以下变量开放指定来源：

```powershell
$env:CAMPUS_CORS_ORIGINS = "http://127.0.0.1:8000,http://localhost:8000"
```

## 15. 联调问题定位

### 页面显示“实时连接已断开”

检查：

- `CAMPUS_WS_BASE_URL` 是否使用 `ws://` 或 `wss://`；
- WebSocket 是否校验了错误的 Cookie 域；
- 反向代理是否启用了 Upgrade/Connection 头；
- HTTPS 页面是否错误连接 `ws://`。

### REST 正常但视频不显示

检查：

- `/video_feed` 是否返回正确 `Content-Type`；
- boundary 是否确实为 `frame`；
- JWT 是否只能通过 Authorization，而 `<img>` 无法携带；
- 代理是否缓冲了无限流响应。

### 数据显示为“—”

这是 `null` 的正常表现。检查后端是否真正返回了数字，而不是缺失字段、空字符串或 `null`。

### 跨域请求没有 Cookie

检查：

- 前端请求已经使用 `credentials: include`；
- 后端允许具体 Origin 和 Credentials；
- Cookie 的 Domain、SameSite、Secure 是否匹配；
- 本地调试不要混用 `localhost` 和 `127.0.0.1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/users` | 返回用户列表，不得返回 `password_hash` |
| POST | `/api/users` | 创建用户 |
| PUT | `/api/users/{id}` | 修改角色、显示名、状态或密码 |
| DELETE | `/api/users/{id}` | 删除用户 |

创建请求：

```json
{
  "username": "security01",
  "password": "change-me",
  "role": "security",
  "display_name": "安保值班员",
  "is_active": true
}
```

用户响应只能包含公开字段，例如 `id`、`username`、`role`、`display_name`、`is_active`、`created_at`。后端必须阻止删除或禁用当前用户，并保证至少保留一个有效管理员。

### 16.2 演示辅助接口（课程模式）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/demo/init` | 幂等初始化演示数据 |
| POST | `/api/demo/trigger/{alarm_type}` | 触发指定模拟告警 |
| POST | `/api/demo/run` | 运行预设演示序列 |

支持的 `alarm_type` 至少包括：`fence`、`crowd`、`fall`、`smoke`、`temperature`、`blacklist`。这些接口用于课程演示，生产部署应通过配置关闭或限制为管理员访问。

## 17. 后端交付清单

另一位后端开发者完成接入时，应一起交付：

- 可访问的 API、WebSocket 和视频流基址；
- `/api/integration/manifest` 的实际响应；
- 登录方式、测试账号和角色说明；
- 数据库初始化或迁移脚本；
- 环境变量样例；
- CORS 与反向代理配置；
- 模型、摄像头和硬件不可用时的降级策略；
- 至少一组告警、门禁、传感器和地图联调数据；
- `/docs` 或等价 OpenAPI 文档；
- 启动、停止、日志和故障排查说明。

前端联调时重点保留以下文件：

```text
app/static/js/api-client.js
app/templates/base.html
app/templates/monitor.html
app/templates/dashboard.html
app/templates/alarms.html
docs/后端接入手册.md
```

完成替换后，必须再次验证登录、`/monitor`、`/dashboard`、`/events`、WebSocket、MJPEG、截图地址和移动端布局。
