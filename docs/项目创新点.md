# 项目创新点

## 一、多源校园安全信息融合

系统不是单一的目标检测页面，而是将视频 AI、电子围栏、烟火识别、门禁、访客、传感器、校园地图和态势大屏整合为一个可运行 MVP。不同来源的事件最终进入统一告警中心，形成“发现、记录、推送、展示、处置”的业务闭环。

## 二、低成本完整模拟能力

针对课程答辩常见的硬件和网络限制，系统设计了完整降级路径：

- 无摄像头时生成模拟校园画面
- 无 YOLO 模型时生成 mock 人员检测结果
- 无烟火模型时使用 OpenCV HSV 规则
- 无门禁硬件时模拟人员和访客通行
- 无传感器硬件时定时生成采样数据
- 无地图图片时使用 CSS 绘制校园平面图

因此一台普通 Windows + Python 3.11 电脑即可演示全部核心流程。

## 三、实时告警联动

告警创建后会同时完成：

1. 写入 SQLite。
2. 有视频画面时保存证据截图。
3. 通过 WebSocket 推送。
4. 更新监控页的实时消息。
5. 让地图点位变红或闪烁。
6. 刷新大屏指标和最新告警。

这种多页面同步体现了安防系统的实时性，而不只是静态 CRUD。

## 四、面向答辩的工业监控交互

系统采用紧凑、可扫描的深色监控界面，首页、视频监控、智能分析、事件中心、设备管理和系统设置形成清晰的信息架构。大屏数据卡片、高危红色状态、实时钟、自动滚动告警和地图联动均服务于现场演示，不依赖复杂前端框架。

## 五、真实数据与可解释空值

统计接口使用数据库中的真实告警、设备和传感器数据。尚未接入的高级 DS 指标不使用随机数或伪造值，而是返回 `null`，前端显示“—”或“暂无数据”。这种做法使演示结论可解释，也为后续模型接入保留稳定字段。

## 六、前后端契约解耦

前端通过 `CampusAPI` 统一适配 REST、WebSocket、静态资源和 MJPEG 地址，并提供：

- `CAMPUS_API_BASE_URL`
- `CAMPUS_WS_BASE_URL`
- Session Cookie
- 可选 Bearer Token
- 契约版本 `1.0`
- `/api/integration/manifest` 机器可读清单

这使另一位开发者可以替换后端，而无需重写所有页面请求代码。

## 七、成熟组件与可控降级结合

人员检测优先使用 Ultralytics YOLO，视频处理使用 OpenCV，Web 服务使用 FastAPI，数据层使用 SQLAlchemy。系统利用成熟开源组件处理通用能力，同时对模型下载失败、摄像头占用、空数据、WebSocket 断开等情况提供友好降级。

## 八、隐私友好的门禁设计

项目不实现真实人脸识别，只保留人员信息、门禁设备、认证方式和模拟通行记录。这样既能展示门禁业务逻辑，又避免采集生物特征带来的隐私、合规和算法复杂度。

## 九、复合风险预留

系统能够将视频烟火识别与烟雾传感器状态组合为更高等级风险，例如 `fire_risk_high`。这一思路可继续扩展为多摄像头、多传感器和时序模型的联合判断。

## 十、工程可靠性

- 默认数据自动初始化
- 告警冷却避免重复刷屏
- 视频停止时释放摄像头资源
- 输入数据经过 Schema 校验
- 页面按角色授权
- 默认端口占用时自动选择可用端口
- 提供 `install.bat`、`start.bat` 和完整运行文档
- 提供 compileall、导入、登录、页面、API、WebSocket、MJPEG 和发布包自检记录

## 十一、与普通检测 Demo 的区别

普通检测 Demo 通常只显示模型框选结果。本项目进一步实现了：

- 检测结果转化为结构化告警
- 告警证据持久化
- 门禁和传感器业务联动
- 地图定位和大屏统计
- 权限与审计入口
- 模拟硬件和异常注入
- 可替换后端的版本化接口

因此项目更接近一个可展示、可扩展的小型校园安防系统，而不是单独的算法脚本。
