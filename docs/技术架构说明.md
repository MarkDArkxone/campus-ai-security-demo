# 技术架构说明

> 系统版本：2.0.0  
> 技术栈：Python 3.11 + FastAPI + SQLAlchemy + SQLite + OpenCV + YOLOv8 + Jinja2 + 原生 JavaScript

## 一、总体架构

系统采用轻量分层架构，在一台 Windows 电脑上即可完整运行：

```text
浏览器
  ├─ Jinja2 页面与原生 HTML/CSS/JS
  ├─ CampusAPI 统一请求适配层
  ├─ REST API
  ├─ WebSocket 告警通道
  └─ MJPEG 视频流
          ↓
FastAPI 应用层
  ├─ 页面路由与权限校验
  ├─ API 契约与数据序列化
  └─ Session / 可选 Bearer Token 接入
          ↓
业务服务层
  ├─ VideoService
  ├─ AlarmManager
  ├─ AccessService
  ├─ SensorService
  ├─ DashboardService
  └─ WebSocketManager
          ↓
能力与数据层
  ├─ OpenCV / Ultralytics YOLO / mock 检测
  ├─ SQLAlchemy ORM
  ├─ SQLite
  └─ snapshots 静态证据文件
```

## 二、后端模块

| 模块 | 文件 | 职责 |
|---|---|---|
| 应用入口 | `app/main.py` | FastAPI 实例、页面/API/WebSocket 路由、生命周期管理 |
| 配置 | `app/config.py` | 视频源、模型、阈值、数据库、跨域和外部后端配置 |
| 数据库 | `app/database.py` | Engine、Session、建表与默认数据初始化 |
| 数据模型 | `app/models.py` | 用户、告警、门禁、访客、传感器、地图点位 |
| 数据契约 | `app/schemas.py` | 请求体校验与接口字段约束 |
| 鉴权 | `app/auth.py`、`app/dependencies.py` | 密码哈希、Session 用户、角色权限 |
| 告警管理 | `app/alarm_manager.py` | 冷却控制、截图、入库、WebSocket 广播 |
| 视频服务 | `app/services/video_service.py` | 采集、检测、规则、绘制和 MJPEG 帧 |
| 传感器服务 | `app/services/sensor_service.py` | 三秒模拟采样、阈值判断和异常注入 |
| 门禁服务 | `app/services/access_service.py` | 模拟通行、黑名单判定和通行记录 |
| 大屏服务 | `app/services/dashboard_service.py` | 告警、设备、人数和 24 小时趋势统计 |

## 三、检测架构

### 人员检测

1. 尝试加载 `MODEL_NAME` 指定的 Ultralytics YOLO 模型。
2. 对每帧只保留 `person` 类别。
3. 输出边界框、置信度、类别和中心点。
4. 模型加载失败时切换为 mock 人员结果，保证演示不中断。

### 安防规则

- 电子围栏：使用 `cv2.pointPolygonTest` 判断人员中心点是否进入多边形。
- 人员聚集：同帧人数达到配置阈值时触发。
- 疑似跌倒：边界框宽高比超过阈值并持续多帧时触发。
- 烟火识别：优先加载自定义 YOLO 模型，否则使用 OpenCV HSV 颜色规则。

### 视频降级链路

```text
摄像头/本地视频 → 正常视频帧
读取失败          → 模拟校园画面
YOLO 可用         → 模型检测
YOLO 不可用       → mock 人员检测
烟火模型可用      → 模型检测
烟火模型不可用    → HSV Demo 检测
```

## 四、前端架构

前端不使用 Vue、React 等框架，页面由 Jinja2 渲染，交互由原生 JavaScript 完成。

### 主要页面

- `/dashboard`：数字孪生态势总览
- `/monitor`：实时视频监控
- `/analysis`：风险与趋势分析
- `/events`：事件中心，`/alarms` 保留兼容
- `/devices`：统一设备状态
- `/settings`：系统配置与诊断
- `/access`、`/visitors`、`/sensors`、`/map`、`/users`：业务管理页面

### 统一 API 适配层

`app/static/js/api-client.js` 提供 `CampusAPI`：

- REST 基址：`CAMPUS_API_BASE_URL`
- WebSocket 基址：`CAMPUS_WS_BASE_URL`
- 契约版本：`1.0`
- 同源模式自动携带 Session Cookie
- 可选 Bearer Token
- 统一 JSON、静态资源、视频流和 WebSocket 地址生成
- 统一超时、错误和非 JSON 响应处理

该设计允许前端继续使用当前 FastAPI 后端，也允许将 API 切换到另一套独立后端。

## 五、实时通信

### WebSocket

`/ws/alarms` 向监控页、地图页和大屏推送新告警。消息核心字段包括：

```json
{
  "event_type": "access_denied",
  "event_level": "high",
  "message": "黑名单人员尝试通行",
  "snapshot_path": null,
  "created_at": "2026-09-23T20:00:00"
}
```

### MJPEG

`/video_feed` 返回 `multipart/x-mixed-replace` 流，浏览器可直接通过 `img` 元素显示。该方式无需复杂播放器，适合本地演示。

## 六、数据架构

SQLite 数据库位于 `data/campus_security.db`，主要表：

- `User`
- `AlarmEvent`
- `Person`
- `AccessDevice`
- `AccessRecord`
- `VisitorRecord`
- `SensorDevice`
- `SensorData`
- `MapPoint`

系统启动时自动建表，并初始化默认管理员、门禁设备、传感器和地图点位。密码使用哈希保存，不存储明文。

## 七、核心业务流

### 告警流

```text
检测/传感器/门禁规则
  → AlarmManager 冷却判断
  → 保存证据截图（存在画面时）
  → 写入 AlarmEvent
  → 更新关联地图状态
  → WebSocket 广播
  → 监控、事件、地图和大屏刷新
```

### 传感器流

```text
后台定时任务（每 3 秒）
  → 生成安全范围数据
  → 写入 SensorData
  → 与阈值比较
  → 超限时创建告警
```

### 门禁流

```text
选择人员和设备
  → 校验人员状态
  → 写入 AccessRecord
  → 正常人员 allowed
  → 黑名单/禁用人员 denied + access_denied 告警
```

## 八、安全与权限

- Session 中间件维护登录态。
- 页面路由按角色校验，未登录重定向到 `/login`。
- 无权限页面返回统一 403 页面。
- 管理接口进行身份和角色检查。
- 密码通过 PBKDF2 哈希保存。
- 外部前后端分离时可配置精确 CORS 白名单。
- 不实现真实人脸识别，降低隐私与合规风险。

## 九、部署模式

### 单体同源模式

运行 `python run.py`，FastAPI 同时提供页面、API、WebSocket、视频流和静态资源。这是课程答辩的推荐模式。

### 前后端分离模式

通过环境变量设置 API 和 WebSocket 基址，由 `CampusAPI` 连接独立后端。独立后端需要实现 `docs/后端接入手册.md` 中的契约，并正确配置 CORS、鉴权和流媒体地址。

## 十、边界与限制

- 跌倒检测是规则模拟，不是姿态模型或医学诊断。
- HSV 烟火识别会受到颜色和光照影响。
- 数字孪生为二维/伪三维可视化，不是真正三维引擎。
- 高级 DS 指标未接入时返回 `null`，前端显示“—”，不生成虚假分析结果。
- SQLite 适合单机 Demo；多用户生产部署应迁移到独立数据库和任务队列。
